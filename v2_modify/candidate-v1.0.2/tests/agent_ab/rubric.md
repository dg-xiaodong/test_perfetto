# 评分判据（3 个任务 × 3 分，单任务 0-3）

被测评测对象：同一模型、同一工具条件，分别加载旧版/候选版 Skill，首轮作答；不提供历史纠错与预期答案。

## T1（执行前提）
- +1 检查"实际启动名 basename == config.process_cmdline"，而不是只比主机产物名。
- +1 指出不一致会导致匹配失败、`BLOCKING_INIT` 可能挂起（不是"注意路径"了事）。
- +1 区分静态检查（动态 ELF/名称/schema）与运行期证据（notify-fd 字节、trace 内容、stats/日志）。

## T2（目标发现）
- +1 候选查询覆盖路径名（`name='X' OR name GLOB '*/X'`）并输出 dumps/记录数。
- +1 歧义规则：仅一个 data-bearing 才用；多个 → 报歧义；用户给了 PID/UPID 不替换。
- +1 说明 `-1` = 未解析，0 行 ≠ 没有分配，后续 SQL 复用同一参数。

## T3（A/B 判读）
- +1 明确 interval ≠ 可见 dump 数（受分配推进/去重影响）。
- +1 逐项判定正确：总量/free（有数据）判 PASS；live（有数据）判 PASS/UNKNOWN 且说明；
  **符号在题面未提供 frame/mapping 时，UNKNOWN 是正确输出，不得要求 PASS**；
  精确持有区间判 UNKNOWN 并说明原因。
- +1 判定纪律：不因 `dur=0` 全判未知；**在"精确持有 UNKNOWN"之后，不得再用配置 interval 断言"与 8 秒不符"**
  （interval 只能给上界，不能当实测）。

> 本轮修正：旧判据把"符号必须 PASS"当作得分点，与题面（无符号数据）矛盾；已改为接受 UNKNOWN。
